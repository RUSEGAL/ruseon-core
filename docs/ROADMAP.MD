# Дорожная карта (Roadmap)

## Текущий статус: Этап 13

- [x] **Этап 1: Базовая архитектура и сервер** (Настройка проекта, конфигурация, логгер, Gin-сервер).
- [x] **Этап 2: Подключение RTSP-клиента** (Реализация пула потоков, переподключение, сбор статистики).
- [x] **Этап 3: Парсинг RTP и Ring Buffer** (Декодирование RTP в NALU H264, реализация RingBuffer для zero-copy, извлечение SPS/PPS).
- [x] **Этап 4: HLS Muxer (MPEG-TS)** (Упаковка H264 NALU в TS-сегменты, генерация m3u8, обработка плейлистов в Gin).
- [x] **Этап 5: MP4 Recorder / Архиватор** (Запись fMP4, ротация по часам, политика хранения retention days, очистка старых записей).
- [x] **Этап 6: Web UI (React + TypeScript)** (Сетка/список камер, расширенная статистика сервера, настройка камер и записи, темная тема).
- [x] **Этап 7: Refactoring & Tracking** (Разделение App.tsx на компоненты, ClientTracker для HLS, вывод IP адресов зрителей, настройка GitHub Actions CI & Dependabot).
- [x] **Этап 8: Поддержка H.265 / HEVC** (Парсинг RTP H.265, упаковка в HLS/fMP4, адаптация плеера).
- [x] **Этап 9: Кастомизация камер** (Динамическое управление: создание/удаление пользовательских меток/тегов, добавление произвольных текстовых комментариев, сохранение полей для SIM-карты: номер телефона и ICCID).
- [x] **Этап 10: Биллинг/Трекинг трафика камер** (Расчет потребленного трафика: стартовый лимит 200 ГБ, вычитание на основе принятых байт потока. Персистентное хранение в config.yaml, обнуление 1-го числа каждого месяца, отображение в UI).
- [x] **Этап 11: Умный поиск и фильтрация** (Поиск по ID камеры, имени, пользовательским меткам/тегам, ICCID и номеру телефона. Сортировка списка потоков на фронтенде).
- [x] **Этап 12: Механизм отключения потоков** (Возможность полного отключения потока (Disabled) с указанием причины: Тех. отключение, Отключено по запросу, Отключено за неуплату. Сбор статистики/истории отключений и включений потока).
- [x] **Этап 13: UI/UX Рефакторинг и фиксы** (Минималистичный System Dashboard с информацией об отключенных камерах, фикс выравнивания в List View, динамическое определение кодеков H.264/H.265 через SPS/VPS, исправление сохранения статистики трафика при редактировании камер).
- [x] **Этап 14: Оптимизация HLS-плеера (Авто-ретрай и UI/UX плеера)** (Настройка hls.js для авто-ретраев при старте и обрывах, скрытие дефолтного ползунка и браузерных контролов видео, добавление кастомных состояний загрузки (спиннер), заглушки при потере сигнала, пульсирующего бейджа LIVE и красивого оверлея "Переподключение").
- [x] **Этап 15: Расширенная техническая телеметрия потока** (Добавление в карточку камеры сворачиваемого окна с онлайн-статистикой HLS и RTSP: потерянные кадры, реконнекты, счетчики фреймов, буферизация, битрейт. Обновление в реальном времени).
- [x] **Этап 16: Web-консоль логов сервера** (Добавление кнопки Logs в хедер, перехват и стриминг подробных логов сервера (zerolog) на фронтенд в реальном времени, например через WebSocket или SSE, с возможностью фильтрации по уровню лога).
- [x] **Этап 17: Настоящая JWT-авторизация** (Замена токена-заглушки demo-token-123 в обработчике входа на полноценную генерацию и валидацию безопасных JWT-токенов или сессий для API).
- [x] **Этап 18: Миграция на BadgerDB (Key-Value БД)**
  - [x] **18.1: Ядро БД и слой Storage:** Подключение BadgerDB, создание CRUD-операций (SaveCamera, GetCamera, SaveTag и т.д.) и написание мигратора для импорта старых данных из `config.yaml` в базу при первом запуске.
  - [x] **18.2: Переписывание API и запуска:** Удаление изменяемых данных (камер и тегов) из `config.yaml`, перевод обработчиков веб-интерфейса и логики старта сервера на работу напрямую со Storage-слоем БД.
  - [x] **18.3: Рефакторинг Биллинга и Статистики:** Отвязка фонового сборщика трафика и истории отключений от конфига. Запись статистики и статусов камер напрямую в базу быстрыми атомарными транзакциями без гонок данных.
- [x] **Этап 19: Умный DVR (Timeshift) и Экспорт архива**
  - [x] **19.1: Индексация и API для Таймлайна:** Написание логики для сканирования папки записей камер на диске. Создание API эндпоинта `/api/cameras/:id/archive`, возвращающего доступные временные отрезки (индексы `MP4` файлов) для отрисовки таймлайна во фронтенде.
  - [x] **19.2: Умный Timeshift (HLS из MP4 "на лету"):** Разработка HLS-обработчика для отдачи архива (напр., `/hls/:id/archive.m3u8?start=...`). Чтение `.mp4` файлов через `go-mp4`, извлечение H.264/H.265 NALU без транскодирования и упаковка в TS-сегменты в памяти.
  - [x] **19.3: Экспорт отрезков видео (Склейка MP4):** Эндпоинт `/api/cameras/:id/export?start=...&end=...` для скачивания куска архива. Нативная обрезка и склейка `moov/mdat` атомов MP4 файлов на лету и выдача их клиенту.
- [x] **Этап 20: UI для архива и экспорта (Vue 3)**
  - [x] **20.1: Интеграция HLS плеера для архива:** Добавление возможности просмотра архивных видеозаписей через веб-плеер, загрузка M3U8 плейлистов из `/hls/:id/archive.m3u8`.
  - [x] **20.2: Визуальный таймлайн (Шкала времени):** Отрисовка временной шкалы на основе данных из `/api/cameras/:id/archive`. Удобная навигация, зум и выбор конкретного времени для просмотра.
  - [x] **20.3: Интерфейс экспорта отрезков:** UI-компоненты для выделения отрезка на таймлайне (начало и конец) и кнопка для скачивания выбранного куска MP4 (обращение к `/api/cameras/:id/export`).
- [ ] **Этап 21: UX Рефакторинг модальных окон** (Переработка окон добавления и редактирования камер в более современный, удобный и user-friendly вид).

## Post-MVP
- [x] Инъекция заглушек в HLS-буфер (Failover для сторонних плееров: VLC, OBS и др. Вставка статичного кадра «Потеря сигнала» при обрыве связи с камерой на бэкенде).
- [ ] Ленивый HLS (Lazy Muxing) (Опциональный переключатель. Остановка генерации HLS-сегментов в оперативной памяти при отсутствии зрителей для экономии ресурсов CPU/RAM. Запись в архив при этом продолжается 24/7).
- [ ] WebRTC (Для ультра-низкой задержки воспроизведения <0.5 сек)
- [ ] Дополнительные модули (PTZ-управление ONVIF)
- [x] Защита от сбоев питания (Сканирование и восстановление/«лечение» незавершенных MP4-файлов архива при резком отключении сервера).
