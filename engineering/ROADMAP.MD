## Текущий статус: Развитие Enterprise & Надежности
- [x] **Этап 35: Token-Based Authentication для HLS** (Опционально для каждой камеры - Stateless проверка JWT-токенов в URL плейлистов `?token=...` на лету для защиты потоков от несанкционированного доступа).
- [x] **Этап 36: Fuzzing-тесты для RingBuffer** (Chaos тестирование ядра: запуск 1000 конкурентных писателей и 10000 читателей для гарантии абсолютной потокобезопасности без дедлоков).
- [x] **Этап 37: Динамическое управление конфигурацией (Live API + Swagger)**
  - *Плюсы:* Must-have для Enterprise. Позволяет добавлять камеры "на лету" без даунтайма всего демона. Swagger (OpenAPI) позволяет сразу сгенерировать клиенты на Python/TS.
  - *Минусы:* Требует внедрения потокобезопасного State Manager'а (RWMutex на мапу камер), что усложняет код.
  - *Оптимизация:* Использовать кодогенерацию `swaggo/swag` (0 overhead в рантайме). Состояние маппить напрямую в BadgerDB для переживания рестартов.
- [x] **Этап 38: Инструмент командной строки (ruseon-cli)**
  - *Плюсы:* Отличный Developer Experience (DX) для DevOps-инженеров при дебаге серверов.
  - *Минусы:* Требует поддержки второй точки входа (`cmd/cli`) и синхронизации API.
  - *Оптимизация:* Сделать CLI тонкой оберткой на `spf13/cobra`, дергающей локальный Live API (REST).
- [x] **Этап 39: Тюнинг BadgerDB (Value Log GC)**
  - *Статус:* Реализован ночной крон через `samber/ro/plugins/cron` (`pkg/storage/storage.go`).
  - *Плюсы:* Критически важно для Edge-устройств. Предотвращает разрастание файлов и износ SSD.
  - *Минусы:* Процесс GC создает сильные всплески Disk I/O (может вызвать фризы видеоархива).
  - *Оптимизация:* Обернуть вызов в планировщик (`samber/ro` cron), чтобы запускать строго ночью в периоды минимальной нагрузки с лимитом времени.
- [x] **Этап 40: MQTT Publisher для AI-метаданных**
  - *Статус:* Реализован асинхронный воркер `internal/mqtt.Publisher` на базе `LockFreeRingBuffer` (`paho.mqtt.golang`).
  - *Плюсы:* Превращает сервер в полноценный IoT Edge Gateway для интеграции с шинами данных (Home Assistant, Node-RED).
  - *Минусы:* Добавляет сетевой I/O оверхед на горячий путь.
  - *Оптимизация:* Публикация строго асинхронная. Метаданные сбрасываются в MPSC Lock-Free кольцевой буфер без блокировки gRPC стрима.
- [ ] **Этап 41: Автоматизированные E2E тесты (Testcontainers)**
  - *Плюсы:* Гарантирует проверку полного цикла Ingest -> WebRTC/HLS. Исключает человеческий фактор.
  - *Минусы:* Тесты медленные (docker) и прожорливые в CI.
  - *Оптимизация:* Вынести в отдельный Workflow (например, `nightly.yml`), чтобы не замедлять быстрые Unit/Fuzz-тесты на каждый push.

## RUSEON Enterprise (ruseon-enterprise)
Помимо базового ядра, следующие функции выделены в проприетарную ветку:
- [ ] **Global High Availability (Clustering)** (Синхронизация стейта через Raft, автоматический Failover (миграция) камер при падении сервера-ноды).
- [ ] **GPU Transcoding (NVENC)** (Перекодирование адаптивного битрейта для мобильных клиентов через аппаратное ускорение Nvidia CGO).
- [ ] **S3 Cold Storage Tiering** (Прозрачная и автоматическая выгрузка старых fMP4-записей (старше 7 дней) с быстрого NVMe в Amazon S3 / Minio).
